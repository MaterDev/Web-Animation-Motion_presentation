Is it the same picture?

The table above is not yet a fair fight, and a bench that hides that is the same failure one level up. putImageData writes one hard pixel per mark; arc() writes an antialiased disc; fillRect writes a solid square. Part of any speed difference is simply drawing less. The rules this bench exists to enforce

One. A timing bracket ends at a named sync point, and the name is printed beside the number — a different sync point is a different number. Two. Every instrument ships a positive control, and it runs where the audience can see it. A control must vary the thing the instrument might be missing: the ×10 mark-count control above passes on the blind clock, because mark count scales command submission too. Only the area sweep separates them. Three. When a better instrument inverts a result, the sheet says so, visibly, rather than quietly replacing the figure.

None of these numbers are stage numbers. Playwright's Chromium is not Chrome, and its clock floor here is coarser than Chrome's. The figures that go in front of an audience get taken in Chrome, on the presenting machine, on mains power, with the refresh and dpr printed beside them — as this page prints its own.
