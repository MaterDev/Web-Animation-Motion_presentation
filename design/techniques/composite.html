SL-07

composite

Don't be a purist. Composite is not a technique, so this sheet has no demo. It is the closing argument, made by re-reading what the other sheets already showed: real page elements wherever semantics, interaction and accessibility are needed, a GPU surface wherever they are not, and an alternative for anyone who cannot use the GPU layer. Canvas is a fact about a surface; composite is a way of deciding what goes on which one.

The argument

one page, three surfaces

Composites are a performance strategy, not only an aesthetic one. Put each part of a scene on the cheapest surface that can carry it: DOM where you need semantics, GPU where you need pixels. Keep the parts that move out of the expensive pipeline stages. Purism is often where performance problems come from, because it forces one surface to do work it is bad at.

  1. What the user sees: one page.
    What the browser runs: three surfaces.
  2. DOM · HTML + CSS · on top

    Navigation, headline, price, the buy button and its focus ring. Needs semantics, interaction, accessibility.

  3. Canvas · WebGL / WebGPU

    The product, its light, the particle field. Needs pixels. Nothing inside can be read, so nothing that must be read goes there.

  4. Video · at the back

    The ambient loop. Pre-rendered and fixed, which is fine while it never has to respond.

  5. Alternative · no GPU layer

    A still in place of the canvas. The DOM layer is unchanged, so switching the GPU layer off loses nothing a keyboard or screen reader needs.

For a brief

which technique carries which part?

Make it a question, not a philosophy. The failure mode is a brief that assumes one answer and rules out combining techniques before anyone has looked.

Don't ask
Which technique is this project?

One surface is chosen first and then made to carry everything, including the work it is bad at.

Ask
Which technique carries which part?

Each part goes to the cheapest surface that can carry it, and the parts are coordinated so the whole feels seamless.

Mechanics

how the layers hold together

You cannot put page elements inside a canvas. So the composite is built the other way round, and the rest of this section is what that inversion costs and where it breaks.

Failure modes

  1. Many GPU contexts on one page. A composite is not a license to give every part its own canvas. Many GPU-backed contexts on one page is itself a performance problem: browsers cap live WebGL contexts and silently drop the oldest past the cap, while a WebGPU device can drive many canvases. The paper's context-limits note has the detail; there is no single current number to quote.
  2. Drift. Two layers that each keep their own time will separate, and the first thing to show it is focus (figure F).
  3. Shadow DOM is not an accessibility feature. It is a way of encapsulating components. It does not make anything accessible on its own; the accessible layer you need is ordinary DOM (figure B).
  4. The purist brief. A brief that decides the technique before the parts rules out the cheapest surface for most of them.
  5. The GPU layer drops out of QA. The DOM layer is testable the usual way; the GPU layer has nothing to select and nothing to assert against.

What this sheet is, and isn't

Composite has no demo and no example of its own by design: the other sheets are the examples, read again through this lens. Every figure here is an explanatory diagram. None prints a number, because nothing on this sheet was measured.
