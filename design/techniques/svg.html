The first technique on this spectrum where the picture is made of elements rather than pixels. That single fact is what you are buying: the marks are in the DOM, so CSS styles them, the pointer hits them, a screen reader can be told what they are — and every one of them costs a node, which is also what you are paying. Every demo here is built on one dataset — the documented history of this field, because a technique shown on a coloured square teaches nothing about when to reach for it, and because a sheet that argues its numbers are measured should be arguing it about something real. Thirty events, twenty-two sourced movements between institutions, 1943 to today.

THE TRADE

what a node buys, and what it costs

One decision explains most of this slide. Because every mark is a real element, CSS reaches it, the pointer hits it and a screen reader can be told what it is — and because every mark is a real element, the browser must style, lay out and paint each one. Both halves of that are demonstrated here rather than asserted, and the right-hand one is the whole reason the next slide exists. The graph is a lineage fragment from the dataset the rest of this sheet runs on; the field beside it is what happens when you try to plot everything at once.

every mark is an element

A canvas hands you one element and a bag of pixels. SVG hands you a document. Hover any node — the pointer hits the shape, not its bounding box, and nothing scripts that. The buttons restyle the whole graph from outside it, by putting one class on the root.

THE LINE

a path is a one-dimensional space

stroke-dasharray was designed to draw dashed lines, and it does. But what it actually gives you is a coordinate system that runs along the path — distance from the start, in user units, addressable. Set the dash to the path's own length and there is exactly one dash; slide stroke-dashoffset and you are moving the boundary between drawn and not-drawn along that axis. Nothing is being animated but one number, and no geometry changes. The same number, taken small and repeated, is a marching-ants marquee. Same mechanism, same two properties.

getTotalLength — stroke-dasharray — stroke-dashoffset — drawn — the ghost behind is the same path, undashed — the geometry never changes

Scaled up, that is a whole diagram. Every arc below is one movement between two places in the history of this field — a person changing institutions, a lab spinning out — and each is drawn by the same single number as the year passes it. The marker riding each arc is rotated to the path's own tangent, read back with getPointAtLength; the labels are real HTML pushed into place through getScreenCTM, not SVG text. Watch the gaps — and watch which one is not there. The longest stretch where the axis advances and nothing draws sits on the first AI winter. The second winter does not show up at all: people kept changing institutions straight through it. A diagram of who moved where is not a diagram of who was funded, and this one says so by failing to show the thing you would expect it to. THE FRAME

the camera, and what it costs to move it

Zooming a vector scene is not zooming a picture. There is no camera object — there are three different things people call one, and they are not interchangeable. Pick a driver below and the same scene is framed by a different mechanism: rewriting the root's viewBox, transforming a group inside it, or handing the whole motion to the browser as a paused animation and scrubbing its currentTime. The readouts are all main-thread work — attribute writes, style and layout — which is the kind of cost a frame meter can honestly see, unlike §4 below.

what the bench answered

The driver does not matter. Across Chrome, Safari and Firefox, and across repeated runs, no camera driver is reliably cheaper than another — the ordering changes run to run and the whole spread sits inside the sampling noise of a thirty-frame mean. All three hold full display cadence with zero long tasks. That is a real answer, and it is not the one the plan assumed: this scene is nowhere near the cost of moving a camera, so the choice gets made on other grounds. Nested g wins them: rewriting the root viewBox takes it away from responsive sizing and from the QC filmstrip, and WAAPI cannot express a log-space zoom without being handed sampled keyframes — which is the interpolation you gave it to do.

The hairline strategy is the only control that moves the number, and the one that costs is the only one that works. The middle column is the rule; the third is one measurement of it. They only differ on a 2× display — which is why the readout above prints the dpr it measured at, so the live number and this table can be reconciled rather than read as a contradiction.

vector-effect: non-scaling-stroke is constant, but it pins to one CSS pixel — which on any 2× display is two device pixels, and a hairline that is two pixels wide is not a hairline. Only dividing the stroke width by the zoom lands on one device pixel, and that has to be written every frame, on every stroked element. It is still free here. It stops being free at map scale, which is what §3's stage will have to answer.

Neither reading came from a portable instrument. The thickness above is measured, but no single API measures it everywhere: Firefox implements getBBox({stroke:true}), Chrome and Safari accept the argument and silently ignore it, so a try/catch feature test passes in all three and is wrong in two. Hit-testing the document works in Chrome and Safari and not in Firefox, whose hit region for a non-scaling stroke is not the region it paints. The readout says which instrument produced its number. The same caution applies to the cost figure beside it — performance.now() is clamped to 1 ms in Firefox and Safari and about 100 µs in Chrome, so the bench measures its own clock and prints a bound rather than a fabricated zero.

THE PIPELINE

a render pipeline, and no shader

A filter in SVG is not an effect, it is a graph — primitives wired input to output, declared in markup, evaluated by the browser's raster pipeline. Build it up one stage at a time below. Blur alone smears the alpha of overlapping shapes into one mass; the colour matrix then multiplies that alpha hard enough to snap it back to a crisp edge, and two circles become one body. No path is interpolated anywhere in this — the topology change is free because it happens in raster space rather than in geometry.
