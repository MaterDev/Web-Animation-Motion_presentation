SL-06

layout / css

Motion the browser runs for you. Two quite different jobs share one engine, and this slide keeps them apart. First CSS for layout — animating a page's own structure, driven by scroll position and by the selectors already describing state. Then CSS as a drawing instrument — the same declarations pointed at elements that aren't structure at all, where what comes out is a picture rather than an interface. You declare the start and the end; the engine works out the frames either way.

NOT LAYOUT AT ALL

css as a drawing instrument

Same engine, opposite job. Nothing here is being laid out. These elements carry no structural meaning — they are circles, rulings, glyphs and gradient stops used as pigment, and what comes out is an image rather than an interface. The drawing is done by filter compositing, pattern interference, gradient geometry, a scroll timeline and the axes inside a variable font: no canvas, no SVG, no WebGL, and no script drawing a single frame. (One exception, stated plainly — the aperture card uses a few lines of JS to move the scrollbar, because CSS has no way to animate scroll position. Every frame it produces is still CSS reading that position.) Worth knowing where this ceiling actually sits, because a surprising amount of what gets reached for later in this deck is reachable here — and the cases that genuinely aren't are what earn Canvas and WebGL their slides.

metaballs · blur + contrast Four circles under filter: blur(11px) contrast(26). The blur smears them together, then the contrast snaps the midtones back to a hard edge — so where they overlap they fuse, and where they part they draw a liquid neck between. Metaballs from two filter functions.
moiré · interference Two identical concentric rulings, one rotating slowly against the other under mix-blend-mode: difference. The pattern you see exists in neither layer — it's the interference between them, which is why it races while the rotation crawls.

SCOPE.md · slide 06

"CSS Transitions/Animations + Render Pipeline — browser-managed motion; introduces Layout → Paint → Composite; visual: animated pipeline diagram + simple live hover/transition demo (generic, not the thread demo — keep this one legible)."

Both halves are real. The pipeline diagram is interactive rather than a static graphic: the stage map, the cost readout and the moving specimen are driven from one property table, so the diagram cannot drift out of step with what the specimen is animating. Kept generic per the scope note — no thread demo here.

The examples were rebuilt around Timeless, a fictional newsweekly, after the first pass proved that a technique demonstrated on a coloured square teaches nothing about when to reach for it. The masthead, the section tabs and the contents flyout are page fragments; the CSS is the point but the context is what makes it legible. The identity is deliberately its own — the reusable part of the genre is its grammar, not any real title's trade dress.

Every card runs itself. A demo that has to be poked is a dead demo from the back of a room, so each fragment loops its own technique unprompted. On the three state-driven cards the loop is a default rather than a cage: the moment you click a tab, focus the contents button or open a story, the animation is dropped and the real selector — :checked, :focus-within, :has() — takes over. The two scroll-linked cards run from the clock instead, using the same keyframes you would bind to scroll() or view() in production; only the timeline differs, which is the actual lesson.

Two boundaries are held on purpose. SL-07 measures what this sheet only models: cost. SL-08 owns animating between two arbitrary measured layouts — which is why the expand example stops at 0fr → 1fr, the one layout animation CSS manages unaided, rather than reflowing the whole grid.
